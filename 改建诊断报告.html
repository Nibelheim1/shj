Project Retrofit Diagnosis · H5 Vertical Slice

《小动物山海经》面向「百万 DAU 轻松解压小游戏」的改建诊断

评审对象：prototype/merge_slice.html 合成主线 MVP（7×8 棋盘 · 1–6 阶 · 4 兽 · 7 日疗愈闭环）。本文档基于实机代码走读（data.js / core.js / ui.js / build-dist.js）与全部设计文档（game-concept / gdd-systems / gdd-merge-game 及三审 / 全面审计）。

一句话结论

这个项目「设计过重、增长为零」：美术与「反差萌疗愈」IP 底子极好，但产品形态与「百万 DAU 解压」目标错位——现在是「合成 + 疗愈」的混合模拟器（认知负担重），而决定 DAU 的渠道、裂变、变现三件套几乎全为零。建议重聚焦定位，把反差萌疗愈前置为钩子、把解压手感做成分钟级循环。

1

诊断：一个身份危机 + 四个致命缺口

左图是「设计深度 vs 增长能力」的剪刀差，右侧是逐条证据
六维能力雷达：内容/美术接近满分，渠道/裂变/变现触底 —— 这是典型的「做成了精品 demo，没做成能增长的产品」。

① 身份危机核心

合成 vs 疗愈 互相打架

README 明确「正式入口是合成主线 MVP」，但灵魂是「疗愈」。合成是获得资源的手段、疗愈是展示面，双重认知负担。更关键：gdd-systems.md 里精心设计的 Trust/Heal 双轨 + 对症矩阵（×1.5/×0.5）在 core.js 里基本被架空，只剩 storySteps（3 段故事）+ careDone（一次照料）就触发蜕变。设计重、落地轻。

② 渠道缺失致命 · 10x

独立 H5 到不了百万 DAU

百万 DAU 本质是微信 / 抖音小游戏目标，靠即点即玩 + 分享裂变 + 买量。现状矛盾：architecture.md 规划 Cocos+微信，但实际代码是 vanilla JS + build-dist.js + tcb hosting deploy（腾讯云静态托管）。技术栈与目标渠道脱节，迟早要重写。

③ 裂变 / 社交为 0致命

自评 3/60 社交 · 0/60 竞技

三审报告自己打出的最短木板。现状：featureFlags.rewardedAds=false，无分享卡、无排行榜、无助力、无组队。百万 DAU 在微信生态 = 裂变系数，一个「分享解锁」就能把 DAU 拉高数倍。

④ 留存钩子不足

「任务感」≠「我想回来」

有 7 日闭环、每日目标、体力回充，但都是「任务感」留存。疗愈类天然低留存——一只兽治好就完了。当前 4 兽 6 阶太薄（三审自评「4 兽后动力下降」），而 beast-cast.md 里 13 兽阵容完全没接入。

⑤ 变现为 0致命

百万 DAU 无变现 = 纯烧钱

rewardedAds=false，无广告位、无内购。经济闭环（暖玉/体力）存在但没有「广告/内购」的消费出口。日活百万却 0 收入，服务器成本会拖垮项目。

2

战略：重聚焦定位 —— 从「混合模拟器」到「解压撸兽」

把独一无二的「反差萌疗愈」提到前台，把解压手感做成分钟级循环

现在的定位

  • 既要学合成 + 订单 + 体力，又要学照料 + 小游戏，双重认知负担
  • 反差萌是「9 阶信物 → 登场」的结尾奖励，约 20 分钟才看得到
  • 合成 / 订单 / 体力 = 「任务感」，与「解压」背道而驰
  • 4 兽 6 阶，收集钩子太薄
  • 无分享、无社交、无广告、无埋点

应该的定位

  • 第一屏就是一只「炸毛怂包穷奇」，3 秒看懂、第一反应是「也太可爱了吧」
  • 分钟级解压循环：撸它（摸/梳/喂/玩）→ 即时爽感 → 变软一点点 → 蜕变
  • 合成降级为「收集撸兽材料」的副循环（可选、不设体力硬门槛）
  • 13 兽阵容全接入（数据已备好，成本低）
  • 蜕变瞬间 = 可一键分享的「收容所日报」+ 裂变入口

建议的核心循环（解压优先，秒懂秒爽）

看见软萌凶兽→ 撸它（摸/梳/喂/玩）→ 即时爽感反馈→ 它变软一点点→ 蜕变瞬间→ 分享 / 解锁下一只
对照三审报告里已认可的判断：合成类适合做「资源获得层」，庭院与照料才应是「展示面 + 情感层」。当前实现恰好把这个顺序做反了——合成被扶正为主角，疗愈被压成收尾奖励。

analytics: [] 现在是空转。接入真实事件上报，盯 4 个指标：次留 / 3 留 / 7 留、裂变系数 K、LTV、ARPU。

P1-1

离线回归惊喜、兽会「想你」、随机小剧场、天气事件，把「任务感」换成「我想回来看看它」。
P1-4
轻社交

一条必须直说的真相

关于「百万 DAU」这件事的诚实结论

百万 DAU 主要是「渠道 × 裂变 × 买量」的工程题，不是「内容深度」的设计题。

这个项目在设计上已经足够深——甚至过度（3 份 GDD + 三审报告 + 全面审计 + 18 个系统），但增长三件套几乎为零。市面上解压小游戏很多，但「把山海经凶兽撸软」这个定位还没有头部玩家——这才是你唯一能差异化突围的护城河。

DAU = 即点即玩（渠道） × 分享裂变（社交） × 留存（情感钩子） × 买量（LTV>CPA）

不要把反差萌疗愈埋在合成后面——把它推到前台当钩子，把解压手感做成循环，把裂变和变现的「轨道」先铺好。内容随时能补，增长轨道不铺，永远到不了百万。
