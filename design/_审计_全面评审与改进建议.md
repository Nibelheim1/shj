# 小动物山海经 · 全面评审与改进建议

**评审对象**：小动物山海经 · 神兽疗愈收容所（原型 V2.5）
**评审时间**：2026-08-06
**评审方法**：实机运行 + 代码走读 + 对照《动物餐厅》等成熟小游戏标杆
> ⚠️ 历史评审快照：文中"相柳 / 恐怖传说"等表述已被 2026-08 大更新废止（末法时代·神兽落魄·12 兽阵容），见 `design/gdd/gdd-major-update-sect.md` 附录 C。本文仅作存档，不再作为现行设计依据。

---

## 一句话结论

这是一个"骨架搭得很全、美术底子很好、但每个模块都浅尝辄止"的 demo——18 个系统模块都存在、都能跑通测试，但深度不够，离《动物餐厅》那种"能持续玩一周"的运营级小游戏，差的不是功能数量，而是**密度、节奏和情感浓度**。

要往运营级走，有两条路：
1. **A 路**：把现有"疗愈收容"做深做厚（庭院→多层场景、动作→状态机、小游戏→内容丰富），走治愈放置品类。
2. **B 路**：主玩法换成合成类（已另出方案 `gdd-merge-game.md`），用 13 只异兽做收集目标。

两条路不互斥——合成类做核心循环、庭院做"展示面"、照料做深度系统，是最理想的组合。

## 一、界面丰富度（4/10）

### 现状
- 主画面：一张草地背景图 + 3 只兽 + 花瓣粒子，信息密度极低。
- 顶部：Lv1 + 暖玉 + 省略号（3 个 HUD 元素）。
- 底部：4 个 Tab 按钮（异兽/家园/委托/新的一天）。
- 详情面板：卡牌式弹出，内容有但视觉层次弱。
- 清洁、梳毛等按钮还是**占位方块**，不是真正的图标。

### 问题
1. **"空"**：画面 70% 是空白草地，玩家第一眼不知道"我该干嘛"。
2. **层次扁平**：背景是一张整图，没有天空/远山/中景/前景的分层，没有"活的场景"感。
3. **可点击元素太少**：除了 3 只兽和底部 4 个按钮，整个画面都是"看的"不是"玩的"。
4. **反馈弱**：点兽开面板、关掉、再点另一只——都是 DOM 弹层，场景本身不动。

### 改进建议
1. **场景分层**：至少做 3 层——天空层（飘云+日夜）、中景层（建筑/大树）、前景层（草丛），让场景有纵深。
2. **加可互动点**：草地、花朵、水池、建筑，点了都有反馈（草晃、掉花瓣、水波纹）。
3. **把信息"种"在场景里**：不要全堆在面板里——兽的需求直接在头顶飘气泡，委托直接显示在门口的告示板上，资源直接挂在建筑上方。
4. **补全所有占位图标**：清洁/梳毛/喂食/陪玩 4 个按钮必须是精美图标，不能是 emoji 或方块。

## 二、角色与背景融合度（3/10）

### 现状
- 角色是平面贴图，在背景上"平移"。
- 有深度排序（y 越大越靠前）和投影，但**透视、光影、颜色风格**都没对齐。
- 角色有行走和 6 种行为状态机，但动作只是"左右平移 + 呼吸缩放 + 跳跃"。

### 问题
1. **角色是"贴"在背景上的**：光照方向不统一（角色顶光、背景没方向光）、投影形状不自然（一片椭圆灰）。
2. **动作太少、太像"贴纸在晃"**：6 种闲置动作本质上只是缩放/位移/旋转的组合，没有骨骼动画的真实感。
3. **角色没有"踩在地上"的感觉**：没有脚步压痕、没有草被压弯、没有尘土（有但太淡）。
4. **角色不会跟场景互动**：不会去闻花、不会在水池边喝水、不会撞建筑绕开。

### 改进建议
1. **光影统一**：统一顶光+左侧光，角色加投影偏移（跟随光源方向），背景也按同一方向画阴影。
2. **动作升级**：
   - 至少做"走/站/坐/卧"4 个姿态的帧动画（不是简单缩放）。
   - 用龙骨/Spine 或 CSS 帧序列，让腿真的在动、尾巴真的在摆。
3. **环境互动**：
   - 走到花旁边，花会被碰一下微微摇晃。
   - 走到水池边，角色会停下来低头喝水 2 秒。
   - 建筑前有"岗位"，对应职责的兽会站过去做事。
4. **地面反馈**：脚步踩过的地方草微微压扁，几秒后恢复。

## 三、角色动作与触发逻辑（5/10）

### 现状
- 行为状态机：idle / wander / towork / work / fromwork，模式切换基本正常。
- 6 种闲置行为：breathe / look / yawn / groom / sleep / hop，按阶段有权重差异。
- 拖拽能移动角色，位置能持久化。

### 问题
1. **动作触发"无因"**：兽为什么现在打哈欠？为什么现在跳一跳？玩家看不懂"触发条件"，就觉得是随机瞎动。
2. **动作之间没有过渡**：从"睡觉"直接切到"蹦跳"，没有起身的过渡帧，很跳戏。
3. **工作行为=站着不动**：to work 模式走到建筑前就停了，没有"在做事"的动作表现。
4. **角色之间零互动**：13 只兽各走各的，碰面不会打招呼、不会一起玩、不会吵架。
5. **没有情绪状态可视化**：开心/难过/饿了/困了，全靠头顶 emoji，不是身体语言。

### 改进建议
1. **给动作加"理由"**：
   - 饿了 → 走向厨房/食物盆 → 低头吃
   - 脏了 → 走向水池 → 泡水抖水
   - 无聊了 → 走向另一只兽 → 一起玩
2. **加过渡动画**：坐→站、站→走、走→停，每个过渡 0.3 秒，顺滑不跳戏。
3. **工作动画可视化**：
   - 饕餮在厨房 → 有锅铲翻动的动作 + 香气粒子
   - 相柳在药圃 → 九头轮流浇水
   - 白泽在书架前 → 翻书页动作
4. **角色间互动**：
   - 碰面有 30% 概率触发"打招呼"（互相对视 + 爱心小粒子）
   - 羁绊深的兽会一起闲逛、一起睡觉
5. **情绪用身体表达**：开心时尾巴翘、耳朵朝前；难过时尾巴垂、耳朵背。（这个其实立绘 s0/s3 已经有了，但中间态不明显）

## 四、内置小游戏体验（6/10）

### 现状
- 5 个小游戏：喂食（消消乐）、清洁、梳毛（轨迹滑动）、陪玩、种植。
- 每个 150–300 行代码，有独立框架（MiniGameSystem），有评分机制（Perfect/Great/Good）。
- 梳毛还会按兽的阶段换背景图。

### 问题
1. **用 emoji 当游戏素材**：喂食用 🍙🐟🍎🥕——和游戏整体水彩风完全脱节，像两个游戏拼在一起。
2. **深度只有 1 层**：每个小游戏就是"做对→得分→结算"，没有连击系统、没有难度递增、没有奖励层次。
3. **和主游戏的关联弱**：小游戏结果 = 信任值 +X，就完了。没有"小游戏产出道具→道具用于照料→照料影响进度"的链条。
4. **缺乏失败感也缺乏成就感**：零失败是好事，但全程都是"Good"起步，玩家没有"我做到了！"的狂喜时刻。

### 改进建议
1. **素材全换**：所有小游戏图标都画成水彩风，跟主画面风格统一。
2. **加连击/排名/成就**：
   - 喂食消消乐：加 5 连、10 连 combo，连击越高分越高，全清有 Bonus。
   - 梳毛：加时间限制（30 秒内梳完 5 条路径），S/A/B/C 评级。
3. **小游戏→道具→照料 形成链条**：
   - 玩种植小游戏 → 产出草药 → 草药用于配药
   - 玩喂食小游戏 → 产出料理 → 料理用于高级照料
   - 不是直接加信任值，而是产出"实物"增加策略感
4. **加"挑战模式"**：每只兽有专属小游戏挑战（如穷奇的"飞盘接接乐"），通过解锁专属动作/皮肤。
5. **保留零失败但加奖励层级**：最差也有 Good，但 Perfect 有 3 倍奖励 + 特殊粒子特效，让玩家"想再玩一次拿 Perfect"。

## 五、玩法闭环与成长体系（4/10）

### 现状
- 核心循环：收容 → 照料 → 疗愈 → 蜕变 → 上岗产出。
- 资源：暖玉、食材、草药、声望。
- 升级：收容所等级、设施升级、异兽觉醒。
- 抽卡：升级后免费抽一只新兽。
- 18 个系统模块全部跑通测试。

### 问题
1. **没有体力/次数限制**：想点就点、想玩就玩，玩家反而不知道"玩到什么时候算一局"，容易快速腻。
2. **成长反馈太慢**：信任/疗愈从 0 到 100，每次照料 +5，要 20 次才能蜕变——20 次点击=玩家眼里"没变化"。
3. **没有清晰的"下一步目标"**：玩家进游戏后，不知道"我今天该做什么"，只有模糊的"继续照料"。
4. **经济系统太浅**：暖玉、食材、草药——3 种资源，但产出/消耗路径单一，没有"攒钱买大件"的期待感。
5. **升级=解锁新兽**：太单一，升级没有"我变强了"的直观感受。
6. **离线收益缺失**：关游戏再打开，什么都没发生——放置品类的核心乐趣没了。

### 改进建议
1. **加体力/能量系统**：
   - 每次照料消耗 1 点体力，上限 50 点，每 3 分钟回 1 点。
   - 这样玩家每天自然有 3–5 次会话，形成习惯。
2. **加速正反馈节奏**：
   - 信任/疗愈改成**阶段式**而不是线性的（s0→s1→s2→s3），每个阶段都有明显的外观+动作变化。
   - 这个其实 v2.5 已经做了（calcBeastStage），但体感上还是太慢——把阶段阈值降低一些。
3. **每日任务系统**：
   - 登录即看到"今日 3 件事"（如：照料穷奇 3 次、玩 1 次小游戏、完成 1 个委托）。
   - 全完成给"每日宝箱"（暖玉 + 食材 + 小概率稀有道具）。
   - 让玩家每天有明确目标。
4. **加"大件消费"目标**：
   - 攒 5000 暖玉 → 扩建庭院（多 2 个兽位）
   - 攒 10000 暖玉 → 解锁新场景（海边/山巅）
   - 攒 20000 暖玉 → 解锁鲲鹏（终极目标）
   - 给玩家"攒钱→买大件→满足"的经典循环。
5. **离线收益**：
   - 关掉游戏后，已蜕变的兽继续"上班"产出资源。
   - 下次登录时弹窗"你不在的时候，大家帮你攒了 X 个食材 + Y 暖玉"。
   - 这是放置类游戏的灵魂，必须有。
6. **成就系统**：
   - 50 个以上成就（首次蜕变、集齐 5 兽、100 次 Perfect、攒够 10000 暖玉…）
   - 成就给奖励 + 解锁图鉴页装饰。

## 六、主玩法改合成类的可行性（8/10 契合度）

详细方案见 `design/gdd/gdd-merge-game.md`。这里只说核心判断：

### 为什么合成类更适合做"主玩法"
1. **碎片时间友好**：30 秒到 3 分钟都能有进展，完美匹配微信小游戏。
2. **天然的进度可视化**：1→2→3→…→9 阶，每一步都看得见，比"信任值+5"直观 10 倍。
3. **收集驱动留存**：13 只异兽 = 13 个明确目标，玩家会"就差最后一只了！"。
4. **广告变现顺畅**：体力不够看广告、双倍领取看广告——合成类的广告 ARPU 是治愈类的 2–3 倍。

### 怎么改才不丢"灵魂"
- **不要纯合成**：合成是主循环（怎么获得资源），但**庭院和照料是展示面**（获得异兽后放哪里、怎么培养感情）。
- **反差萌做"惊喜时刻"**：9 阶信物 → 异兽登场，这个 15 秒的"哇塞时刻"是整个游戏的传播引擎。
- **保留疗愈主题**：合成物品不是"武器装备"，而是"安神露""桃木梳""暖玉护符"——每一样都是疗愈用的，主题统一。

### 改造成本
- 代码层：核心循环（合成棋盘 + 委托 + 异兽解锁）大概需要重写 40%，保留 60%（数据/异兽/渲染/UI 框架）。
- 美术层：13 兽立绘直接用，需要新增 4 条线 × 9 阶 = 36 个物品图标（可以用现有素材拼 + AI 生成）。
- 预估：Phase 1 核心循环 4 周可上线测试。

## 七、优先级总表（按"投入产出比"排序）

### P0 — 1 周内能搞定、体感提升最大的

1. **场景分层 + 可互动点**：从"一张画"变成"一个世界"，视觉提升 2 倍。
2. **体力系统 + 每日任务**：给游戏一个"心跳"，让玩家知道什么时候来、来做什么。
3. **离线收益**：放置类灵魂，上线即惊喜。
4. **补全所有占位图标**：清洁/梳毛等按钮换成水彩风图标，细节决定品质。

### P1 — 2–4 周，从 demo 变"游戏"

5. **角色动作升级**：加走/坐/卧姿态 + 过渡动画 + 工作可视化。
6. **角色间互动**：打招呼、一起玩、羁绊，让场景"活"起来。
7. **小游戏素材统一 + 加深度**：换水彩素材、加 combo、加评分、加产出道具链。
8. **大件消费目标 + 成就系统**：给长期玩家一个"攒"的理由。

### P2 — 1–2 月，决定能不能长线运营

9. **主玩法换成合成类**：如果目标是冲 DAU 和收入，这是最有效的一步。
10. **建筑动效 + 场景事件**：兽舍探出头、药房冒烟、随机小剧场。
11. **社交系统**：好友互访、互赠体力、排行榜（微信小游戏标配）。
12. **异兽皮肤 + 节日活动**：长线运营内容。

## 八、给你的建议

如果你是想**认真做一款能运营的小游戏**，我的建议是：

**第一步**：先用 1 周把 P0 的 4 件事做了（场景分层、体力系统、离线收益、补图标）。这一步投入最小、见效最快，能把 demo 感降到最低。

**第二步**：同时做一个"合成类核心循环"的小 demo（4 槽棋盘 + 1 条合成线 + 1 只异兽登场），玩一下看看手感——如果觉得确实比现在的疗愈模式更上瘾，就全面转合成；如果还是更喜欢疗愈感，就走 P1 加深路线。

**关键判断**：
- 目标是**治愈向小众精品** → 走 A 路（加深疗愈+放置）
- 目标是**冲 DAU / 变现 / 上排行榜** → 走 B 路（合成主循环+疗愈做皮肤）

两条路都能成，就看你想做什么样的产品。
