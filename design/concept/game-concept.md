# 游戏概念文档（Game Concept）

**项目代号**：小动物山海经 · 神兽疗愈收容所（栖霞宗）
**版本**：v0.2（立项概念 · 末法时代修订）｜**负责人**：文策渊（设计 / 叙事）

## 1. 一句话创意定位（Pitch）
> 一座软萌绘本水彩风的"神兽疗愈宗门·栖霞宗"：末法时代灵气稀薄，你把一只只落魄的神兽接进山门，用温柔的照料补足灵气，帮它们重焕精神、各归其位——**把往日的风采，轻轻找回来。**

## 2. MDA 框架分析
"疗愈蜕变"是贯穿三层的主轴，不是贴皮，而是从规则 → 行为 → 情感逐层兑现。

### Mechanics（机制层）
- **收容与落魄档案**：每只神兽入门即生成一份"落魄档案"，记录它的本相（古籍温和一句）如何映射成"初来症状"（如穷奇有翼却扑腾不起来 → 怕生躲门后）。
- **对症温养**：喂食 / 清洁 / 梳毛 / 陪玩四类互动，按"症状类型"匹配才高效（轻度解谜）。
- **焕新进度**：信任值 + 疗愈进度双轨，满格触发"焕新动画"，从落魄态 → 精神焕发态。
- **零失败规则**：任何照料都给正向反馈，没有惩罚、没有倒计时压力。

### Dynamics（动态层）
- 玩家在"试错匹配温养方式"中涌现策略：哪类互动对哪种落魄症状最对症，形成可分享的"疗愈心得"。
- 神兽从落魄态的蔫蔫行为，随灵气补足逐步过渡到神采奕奕，玩家**亲眼见证连续变化**（动态反馈闭环）。
- 焕新后的神兽"上岗"产生职责产出，多个神兽职责互补，自然长出宗门"生态协作"（如饕餮管膳堂 → 喂饱大家 → 省心）。

### Aesthetics（美学 / 情感层）
- 核心美学即**落差萌**：耳熟能详的神话神兽，昔日神骏 / 威严，如今落魄成软萌小动物，焕新后又神采奕奕——惊喜感与分享欲天然产生。
- 情感目标：安心、温柔、共情（"落魄的神兽也有被好好照顾的一天"）、收集成长的满足、"被需要"的暖意。
- 一句话：**让玩家走出游戏时觉得，世界柔软了一点。**

## 3. 设计支柱（Design Pillars）
1. **温柔即解法（Gentle is the Solution）**
   不靠战斗、镇压或数值碾压推进，所有"落魄"都被重新定义为"可被温柔补足的灵气亏空"。玩家的解题工具是耐心与对症的照顾，而非武力——这把山海经神兽的"威"与"萌"彻底揉在一起。
2. **反差即萌点（Contrast is the Charm）**
   知名度越高的神话神兽 + 越落魄的软萌状态 = 越强的记忆点与传播力。每一个形象都要让玩家"一眼认出典籍，一眼被萌到"，反差是产品级卖点而非装饰。
3. **慢节奏的陪伴成长（Slow, Earned Warmth）**
   休闲全年龄向，以"陪伴时长与羁绊深度"而非"效率 / 速度"度量进度。零失败、低认知负荷，让玩家在无害、温暖的环境里慢慢积累关系，拒绝焦虑型留存设计。

## 4. 核心循环（Core Loop）
**一次会话主循环（约 15–30 分钟 / 一天）**
```
收容(Rescue) → 评估(Assess) → 温养(Care) → 疗愈(Heal) → 焕新(Transform) → 产出/解锁(Produce/Unlock)
```
1. **收容**：接到委托 / 事件，选择接哪只神兽进山门（自主选兽）。
2. **评估**：翻开"落魄档案"，了解它的本相是什么、初来有什么症状行为（如怕生炸毛、九尾内耗）。
3. **温养**：喂食 / 清洁 / 梳毛 / 陪玩迷你互动，提升信任值（轻操作、强反馈）。
4. **疗愈**：针对症状做"对症"安排（如穷奇怕生 → 安静角落 + 慢陪伴；麒麟怕辜负期待 → 陪它放下架子）。
5. **焕新**：信任值 / 疗愈进度满 → 触发焕新动画，从落魄态变为精神焕发态，解锁新职责。
6. **产出 / 解锁**：焕新后神兽上岗（饕餮管膳堂、白泽讲故事），产出资源、推进宗门修缮、解锁新委托。

**心流 / 难度曲线落点**
- 难度来自"对症下药"的轻度匹配推理，而非手速或数值。
- 随宗门等级提升，神兽症状更复杂、需组合多种疗愈方式，难度**温和爬升**。
- 零失败保证心流不断流：任何互动都给正向反馈，挫败被设计剔除。

**自我决定论（SDT）三需求落点**
- **自主 Autonomy**：自由选接哪只、怎么布置宗门、用哪种疗愈节奏。
- **胜任 Competence**：落魄档案 + 进度条让"我在让它好起来"清晰可见；焕新动画是强胜任奖励。
- **关联 Relatedness**：与神兽建立羁绊、神兽间职责 / 社交联动；玩家是"被需要的守护者 / 掌门"。

## 5. 目标受众与情感体验
- **核心受众**：全年龄休闲玩家，偏治愈向 / 收集向 / 女性向；国风与山海经文化爱好者；亲子共玩场景。
- **平台**：移动端优先（碎片化 15 分钟会话）、PC 可选（大屏欣赏水彩与图鉴）。
- **想让玩家感受到**：安心、温柔、落差萌的惊喜、"被需要"的满足、对落魄者的共情与守护欲、收集成长的愉悦。
- **一句话体验目标**：在温柔里，把"往日的风采"轻轻找回来。

## 6. 系统设计草图（8 个系统）
| # | 系统 | 一句话职责 | 依赖 |
|---|------|-----------|------|
| 1 | **收容系统** Rescue/Intake | 委托接取、入门评估、生成"落魄档案"与初始症状。 | 无（起点） |
| 2 | **照料系统** Care | 喂食 / 清洁 / 梳毛 / 陪玩互动，产出信任值。 | 1 |
| 3 | **疗愈 / 焕新系统** Healing | 对症温养、推进焕新进度、触发焕新动画（管理信任值 / 落魄态 / 进度）。 | 2 |
| 4 | **经济 / 资源系统** Economy | 货币、食材 / 材料产出与消耗、建造与委托成本。 | 3（职责产出驱动） |
| 5 | **建造 / 宗门系统** Build | 区域 / 设施修缮，提供疗愈环境加成。 | 4（吃资源） |
| 6 | **神兽职责 / 社交系统** Roles & Bond | 焕新后上岗产出、神兽间羁绊与互动。 | 3, 4 |
| 7 | **图鉴 / 收集系统** Codex | 记录已收容神兽、典籍本相、焕新前后对比。 | 1, 3 |
| 8 | **事件 / 委托系统** Events | 新神兽委托、节日活动、访客到访。 | 1 |

**依赖拓扑排序（Tier）**
- Tier 0：收容系统
- Tier 1：照料系统
- Tier 2：疗愈 / 焕新系统
- Tier 3：经济 / 资源系统
- Tier 4：建造 / 宗门系统、神兽职责 / 社交系统
- Tier 5：图鉴 / 收集系统、事件 / 委托系统（整合全部）

## 7. 范围分层（Scope Tiers）
**Phase 1 — 可玩竖切片（Vertical Slice）**
1. 收容 + 落魄档案（3–5 只神兽，完整"症状 → 焕新"流程）
2. 照料迷你互动（喂食 / 梳毛 / 陪玩，1 种轻互动小游戏）
3. 疗愈进度 + 1 次完整焕新动画
4. 最简经济（1 种货币 + 食材产出闭环）
5. 1 个宗门区域 + 基础修缮

**Phase 2 — 扩展（Expansion）**
1. 神兽职责 / 社交系统（上岗 + 羁绊互动）
2. 宗门系统（多区域 / 设施树）
3. 图鉴系统（前后对比 + 典籍卡）
4. 事件 / 委托系统（周期委托 + 轻活动）
5. 神兽扩充至 10+

**远景（Vision）**
1. 跨平台云存档 + PC 大屏鉴赏模式
2. 玩家 UGC 宗门分享 / 互访
3. 季节限定传说神兽 + 文化联动
4. 叙事主线（宗门来历 / 山海温柔重构）
5. 轻度社交（邻里宗门互访馈赠）
