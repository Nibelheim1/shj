# 神兽陪伴礼物闭环（Beast Gift Loop）

> 状态：已实施（prototype v7+）
> 验证：`prototype/tests/h5_beast_gift_loop_test.js`（随 `npm run test:h5` 执行）

## 1. 核心规则

- **不同神兽玩同一款游戏，掉落不同素材**。奖励族由 `beast.careRoutes[groom|play]` 决定，不再由游戏类型单独决定。
- 每只神兽有一个 **成长礼物** `beast.gift`：
  - `gift.care`：送出礼物的游戏（梳洗 / 陪玩）；
  - `gift.family`：礼物所属素材族；
  - `gift.item` / `gift.note`：文案锚点。
- 陪伴奖励物品带 `giftSource`（来源神兽）。**同源礼物合并保留来源**；混入其他来源或普通合成素材后，来源消失，不能再冒充礼物。
- 只有“与指定神兽玩指定游戏”才能拿到对应 `sourceBeast` 素材，因此“必须由某神兽玩耍获得”是硬约束。

## 2. 礼物链（环环相扣）

| 送出者 | 游戏 | 礼物族 | 礼物用途 |
| --- | --- | --- | --- |
| 穷奇 | 陪玩 | 梳妆 groom | 穷奇成长 + 九尾狐来信 |
| 九尾狐 | 陪玩 | 陪玩 play | 九尾狐成长 + 饕餮来信 |
| 饕餮 | 陪玩 | 膳食 food | 饕餮成长 + 帝江来信 |
| 帝江 | 陪玩 | 药材 herb | 帝江成长 + 毕方来信 |
| 毕方 | 梳洗 | 药具 tool | 毕方成长 + 白泽来信 |
| 白泽 | 梳洗 | 建材 build | 白泽成长 + 梼杌来信 |
| 梼杌 | 陪玩 | 符箓 charm | 梼杌成长 + 烛龙来信 |
| 烛龙 | 梳洗 | 珍宝 treasure | 烛龙成长 + 貔貅来信 |
| 貔貅 | 陪玩 | 梳妆 groom | 貔貅成长 + 麒麟来信 |
| 麒麟 | 梳洗 | 陪玩 play | 麒麟成长 + 凤凰来信 |

- `DATA.giftChain` 持久化这 11 段链接；主订单生成时直接读取，避免配置漂移。
- 下一只神兽的 `unlockFamily/unlockTier` 与上一只的礼物族/阶位对齐。

## 3. 订单规则

- **来信 / 招募订单（arrival）**：两份需求都来自上一只神兽的礼物族，且都带 `sourceBeast`。
  例：九尾狐来信 = 九尾手镜（groom T6，穷奇）+ 毛刷（groom T2，穷奇）。
- **成长订单（growth）**：两份需求都来自当前神兽自己的礼物族，且都带 `sourceBeast`。
  例：九尾狐成长 = 嬉云糖塔（play T6，九尾狐）+ 溜溜球（play T2，九尾狐）。
- **主线故事三步**：从卷四起，主素材同样改为该神兽的礼物族，与成长/来信共源。
- 交付与缺料计算 `countItems/consumeRequirement/canDeliver` 全部识别 `sourceBeast`。

## 4. 文案优化

- 庭院按钮显示“与{神兽}{梳洗/陪玩} → 带回{素材族}”，礼物游戏高亮推荐。
- 来信文案由配置自动生成：“和九尾狐一起陪玩，把「嬉云糖塔」与「溜溜球」收进药匣——这是饕餮收到的第一份邀请。”
- 订单需求图标增加“{神兽}礼”角标；成长/来信卡展示 `gift.note`。
- 卷一→卷二钩子：穷奇把玩熟的梳妆礼物收进包袱，为九尾狐的来信铺路。

## 5. 验收

- `h5_beast_gift_loop_test.js`：
  - giftChain 覆盖 12 兽 11 段；
  - 穷奇陪玩 / 九尾狐陪玩 / 饕餮陪玩掉落族互不相同；
  - 九尾狐来信拒绝无来源 groom，接受穷奇来源 groom；
  - 九尾狐成长与饕餮来信只认九尾狐来源 play；
  - 同源合成保留来源，混源合成失去来源；
  - 陪伴奖励真实入库可继续合成。
