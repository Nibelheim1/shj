# 综合系统设计文档（GDD · Systems）
**项目**：小动物山海经 · 神兽疗愈收容所　**阶段**：Phase 2 系统设计
**版本**：v0.1　**负责人**：文策渊（设计 / 叙事）　**对齐源文档**：game-concept.md / beast-cast.md / character-narrative.md

> 全局红线（贯穿所有系统）：**零失败**（无惩罚、无倒计时压力、任何互动均给正向反馈，仅效率高低之分）、**慢节奏陪伴成长**（无衰减扣分、不赶时间）、**三根设计支柱**（温柔即解法 / 反差即萌点 / 慢节奏陪伴成长）；SDT 三需求（自主 Autonomy / 胜任 Competence / 关联 Relatedness）须在每个系统的验收标准中可验证。
> 数值约定：下文所有具体数字均为**示例值，标注（待工程校准）**，用于表达规则与比例，落地前由数值策划与工程联调。

## 0. 通用数值框架（跨系统共享，先定义后引用）

**双轨核心数值**
- `Trust`（信任值）：0–100，初始值由症状严重程度决定（示例 5–20，祥瑞兽 40–50）。
- `Heal`（疗愈进度）：0–100，由对症互动累积；达 100 触发蜕变（祥瑞兽对应"自在度"）。
- `SymptomType`（症状类型枚举）：A 缺乏安全感/护食怕生 · B 容貌/自我认知焦虑 · C 内耗/焦虑/紧绷 · D 机能/节律失调 · E 身份迷茫 · F 表达过载 · G 囤积/资源焦虑。

**四类照料互动基础产出（示例，待工程校准）**
| 互动 careType | 单次耗时 | BaseTrust | BaseHeal | 资源消耗 |
|---|---|---|---|---|
| 喂食 Feed | ~3s | 4 | 3 | 食材 ×1 |
| 清洁 Clean | ~3s | 4 | 3 | 水/清洁布（可无限基础款） |
| 梳毛 Groom | ~4s | 5 | 4 | 无 |
| 陪玩 Play | ~6s | 8 | 5 | 玩具耐久（可无限基础款） |

**匹配倍率 MatchMult（零失败保障：始终为正）**
- 对症（careType 命中该异兽主症状类型）：×1.5
- 非对症：×0.5
- 说明：非对症仍给正反馈（×0.5），但效率仅对症的 1/3，构成"轻度解谜"而不构成挫败。

**环境加成 EnvBonus 与陪伴连击 DailyStreakBonus**
- `EnvBonus = 1 + 0.05 × 环境设施等级`（建造系统提供，见系统 5）。
- `DailyStreakBonus = min(1 + 0.02 × 连续陪伴天数, 1.20)`（慢节奏陪伴成长支柱落点）。

**公式（被系统 2、3 直接引用）**
```
ΔTrust = BaseTrust(careType) × MatchMult × EnvBonus × DailyStreakBonus
ΔHeal  = BaseHeal(careType)  × MatchMult × EnvBonus
Trust_init = clamp(20 − SymptomSeverity × 2, 5, 20)        # 灵兽示例
Trust_init(祥瑞) = clamp(50 − PerfectionPressure × 2, 40, 50)
```

**症状类型 → 最有效互动 对症矩阵（核心解谜表）**
| 症状类型 | 命中主互动 | 次有效 | 代表异兽（来自 beast-cast） |
|---|---|---|---|
| A 缺乏安全感/护食怕生 | 陪玩 | 喂食 | 穷奇、饕餮 |
| B 容貌/自我认知焦虑（渴望被看见） | 梳毛 | 陪玩 | 九尾狐、帝江 |
| C 内耗/焦虑/紧绷 | 陪玩 | 清洁 | 麒麟、凤凰 |
| D 机能/节律失调 | 清洁（毕方擦火花稳脚）/陪玩（烛龙调作息、梼杌被夸） | 梳毛（毕方） | 毕方、烛龙、梼杌 |
| E 身份迷茫 | 陪玩 | 梳毛 | 鲲鹏 |
| F 表达过载/话痨 | 陪玩（倾听） | 梳毛 | 白泽 |
| G 囤积/资源焦虑 | 陪玩（安全感）+ 喂食（规律） | 清洁 | 貔貅、饕餮 |

> 单兽主症状映射见各兽 `primarySymptom` 字段（beast-cast 已含症状描述，本表为其可玩化翻译）。

## 1. 收容系统（Rescue / Intake）　[Tier 0 · 起点]

**1. 概述**
收容系统是玩家与异兽关系的起点：通过事件/委托接取新异兽，生成"落魄档案"（灵兽）或"初来状态"（祥瑞兽），并安置到收容所房间。系统目标是让玩家**自由选择接哪只**（SDT 自主），并立刻获得清晰可读的"它怎么了"信息（SDT 胜任起点）。无上游依赖，是所有后续系统的输入源。

**2. 机制**
- **委托接取**：事件系统（Tier 5）推送委托 → 玩家在「委托」页签查看 → 选择"接它回家"（可暂时不接，不罚）。
- **落魄档案生成**：接取瞬间按 `beastId` 查表生成档案，含字段：`名称 / 典故一句 / 主症状类型 / 初始 Trust / 初来外观状态 / 对应可爱职责`。
- **祥瑞兽特例**：麒麟/凤凰/鲲鹏不套"落魄档案"，生成「初来状态」卡（祥瑞的落魄小烦恼），Trust_init 偏高，蜕变判定复用双轨但文案为"学会做自己"。
- **安置**：拖动异兽到房间空位（建造系统提供空位）；无空位时提示"先搭个房间吧"，不阻断（可暂存候接区）。

**3. 关键数据/数值（示例，待工程校准）**
- 同时收容上限：初始 3 只（随家园等级 +1，上限 13 对应全阵容）。
- 委托冷却：新委托每 1–2 现实日 1 只（慢节奏）。
- Trust_init 范围：灵兽 5–20（依 `SymptomSeverity` 1–5 档），祥瑞 40–50。
- 候接区容量：无限（零失败，不丢委托）。

**4. 公式/规则**
- 档案生成：`档案 = Lookup(beastId) `，字段直接映射 beast-cast 与 character-narrative。
- 初始信任：`Trust_init = clamp(20 − SymptomSeverity×2, 5, 20)`。
- 安置规则：目标房间须有空闲 `slot`；占用 `slot` 后解锁该兽的照料入口。
- 委托去重：同一 `beastId` 未蜕变前不重复推送（避免档案冲突）。

**5. 边缘情况**
- **满员**：已达上限且候接区有 Pending → 提示搭房间，委托保留不消失、不罚。
- **重复委托**：同兽重复推送 → 去重，仅显示首次未接/未蜕变者。
- **祥瑞兽误套灵兽模板**：麒麟等不套"疗愈前症状"，仅"初来状态"，蜕变走"自在度"分支。
- **玩家拒绝委托**：关闭页签即可，无扣分、无冷却惩罚（零失败）。
- **离线期间新委托堆积**：按到达顺序排队，回游戏后一次性告知，不强制处理。

**6. UI 接口**
- 入口页签「委托」：列表卡（异兽剪影 + 一句话诉求 + 接取按钮）。
- 「落魄档案」卡：翻开动画，展示症状类型图标、初始 Trust 条、典故对照短句（引用图鉴文案）。
- 安置：房间视图拖拽 + 空位高亮；候接区角标。
- 空状态文案（引用 character-narrative）："今天没有委托哦，陪大家晒个太阳也好。"

**7. 依赖**
- 上游：无。
- 下游：产出档案/异兽 → 照料（系统 2）、疗愈（系统 3）、图鉴（系统 7）；委托来源 → 事件（系统 8）。

**8. 验收标准**
- [ ] 能接取委托并正确生成落魄档案/初来状态卡，字段与 beast-cast 零冲突。
- [ ] 初始 Trust 按公式落地，灵兽低、祥瑞高。
- [ ] 满员/重复/拒绝三种边缘情况均不罚、不阻断、不丢数据。
- [ ] 安置拖拽成功解锁照料入口；SDT 自主（自由选兽）可在 UI 验证。

## 2. 照料系统（Care）　[Tier 1]

**1. 概述**
照料系统把"温柔即解法"变成可操作的轻互动：喂食 / 清洁 / 梳毛 / 陪玩四类，每次互动按「对症矩阵」结算信任值（核心产出）与少量疗愈进度。设计目标是**强反馈、低认知负荷、零失败**——任何互动都让异兽更软一点，只是对症更快。信任值是疗愈系统的唯一输入。

**2. 机制**
- **选择互动**：在异兽 HUD 点四类按钮之一 → 进入轻互动（抚摸动画 / 迷你小游戏 / 拖拽喂食等）。
- **结算**：小互动完成后调用通用公式结算 `ΔTrust`、`ΔHeal`，飘字反馈（"信任 +X" "更软了～"）。
- **对症提示（轻解谜，非强制）**：落魄档案标注主症状类型图标，玩家可推理"它怕生→陪玩最快"；不提示具体倍率，保留探索乐趣。
- **祥瑞兽**：初来状态同样四类互动，文案为"陪它做自己"（如凤凰顺毛、麒麟一起打滚）。

**3. 关键数据/数值（示例，待工程校准）**
- 四类互动 BaseTrust/BaseHeal 见 §0 表（喂食 4/3、清洁 4/3、梳毛 5/4、陪玩 8/5）。
- 匹配倍率：对症 ×1.5，非对症 ×0.5。
- 单次耗时：喂食/清洁 ~3s、梳毛 ~4s、陪玩 ~6s（可跳过动画）。
- 软上限：单兽单日互动次数无硬上限（零失败），但 DailyStreakBonus 鼓励"每天来一会儿"而非爆肝。
- 资源：喂食耗食材 ×1（基础投喂款不耗，防卡死）；清洁/梳毛无稀缺消耗。

**4. 公式/规则**
- `ΔTrust = BaseTrust(careType) × MatchMult × EnvBonus × DailyStreakBonus`
- `ΔHeal  = BaseHeal(careType)  × MatchMult × EnvBonus`
- `MatchMult`：careType 命中 `primarySymptom` 的主互动 → 1.5；否则 0.5。
- 资源不足降级：无食材时喂食自动用"基础款"（基础投喂），不阻断、不罚。

**5. 边缘情况**
- **资源不足**：喂食无食材 → 用基础款，提示"去厨房找饕餮蹭一口？"（引用空背包文案），不阻断。
- **初期抗拒**：Trust 极低时异兽躲闪，互动仍给正向（×0.5 保底），不扣 Trust、不 Game Over。
- **离线无衰减**：Trust/Heal 离线不降（慢节奏、零失败）；仅长时间未互动显示"它有点想你"提示，无数值惩罚。
- **异兽睡觉（烛龙昼伏）**：睡眠态仅可"轻拍陪玩"，重互动进入队列待醒，不罚。

**6. UI 接口**
- 四类互动按钮（喂食/清洁/梳毛/陪玩），图标区分。
- 异兽 HUD：Trust 条（主）、Heal 条（次，半透明）、症状类型图标。
- 互动小游戏/动画层 + 结算飘字（"信任 +8""尾巴蓬了～"）。
- 反馈文案引用 character-narrative（摸头回应、闲置碎碎念等台词槽）。

**7. 依赖**
- 上游：收容系统（系统 1）提供异兽与档案（含 primarySymptom、Trust_init）。
- 下游：产出 Trust → 疗愈系统（系统 3）；喂食耗食材 → 经济系统（系统 4）；EnvBonus → 建造系统（系统 5）；陪玩/送礼涨羁绊 → 职责社交系统（系统 6）。

**8. 验收标准**
- [ ] 四类互动均可触发并正确结算 ΔTrust/ΔHeal，对症 ×1.5、非对症 ×0.5 生效。
- [ ] 资源不足、初期抗拒、离线三种边缘情况均零失败、不阻断。
- [ ] SDT 关联落点：陪玩可涨羁绊（与系统 6 联调验证）。

## 3. 疗愈 / 蜕变系统（Healing / Transform）　[Tier 2]

**1. 概述**
疗愈系统管理双轨（Trust + Heal）的推进与蜕变判定，是"从落魄到焕新"的兑现点。当 Trust 达门槛且 Heal 满格，触发蜕变动画，异兽从症状态变为稳定可爱态并解锁职责（喂给职责社交系统）。它是核心循环的"成就时刻"，承担 SDT 胜任的强奖励（肉眼可见的变化 + 动画高潮）。

**2. 机制**
- **双轨监控**：实时读取照料系统写入的 Trust / Heal，HUD 双条展示。
- **对症推进**：Heal 主要由对症互动累积（见系统 2 公式）；Trust 由所有互动累积，陪玩最快。
- **蜕变判定**：满足阈值 → 播放蜕变动画（症状态溶解→可爱态成形）→ 弹出职责解锁卡。
- **祥瑞分支**：祥瑞兽无"落魄档案"，Heal 对应"自在度"，达满且 Trust 达标 → "学会做自己"蜕变（文案：麒麟打滚、凤凰开掉毛派对、鲲鹏两态自在）。

**3. 关键数据/数值（示例，待工程校准）**
- 蜕变阈值：`Trust ≥ 60` 且 `Heal ≥ 100`。
- Heal 满需累计：约 20–34 次对症互动（依 BaseHeal 4–5 ×1.5 ÷EnvBonus 估算，慢节奏数日内可达）。
- 门槛意图：Trust 60 保证"先建立安全感再蜕变"，避免只刷 Heal 跳过关系。
- 职责映射：`beastId → duty`（门卫/迎宾/园丁/主厨…），直接取自 beast-cast「职责」字段。

**4. 公式/规则**
- 蜕变条件：`if Trust ≥ TRUST_THRESHOLD(=60) AND Heal ≥ 100: trigger Transform(beast)`。
- 不完全态引导：
  - `Heal ≥ 100 但 Trust < 60` → 提示"它还需要更多安全感（多陪玩）"，不触发。
  - `Trust ≥ 60 但 Heal < 100` → 提示"再对症照料一阵，它就稳了"。
- 蜕变结算：置 `transformed=true`，解锁 `duty`，写入图鉴前后对比（系统 7），开放职责上岗（系统 6）。
- 祥瑞判定：同公式，仅 `TRUST_THRESHOLD` 用其高初始基准，文案分支切换。

**5. 边缘情况**
- **Trust 满 Heal 未满**：阻止蜕变，引导继续对症（不卡死，提示明确）。
- **Heal 满 Trust 未满**：同上，鼓励陪玩补信任（关联需求）。
- **中途切换主症状解读**：玩家换互动类型不影响已累积 Heal，仅边际效率变化（零失败）。
- **祥瑞兽无落魄档案**：走自在度分支，不显示"疗愈前症状"字样，避免设定冲突。
- **蜕变动画播放中离线**：动画状态持久化，回游戏续播或跳过，进度不丢。
- **重复蜕变**：transformed=true 后不再触发，职责卡仅首次弹。

**6. UI 接口**
- HUD 双条：Trust（实色主条）+ Heal（半透明次条）+ 阈值刻度标记。
- 蜕变预告：接近阈值时异兽外观渐变（毛色变软、炸毛收拢）作为预告反馈。
- 蜕变动画层：全屏/聚焦播放，配文案（引用图鉴"如今"句）。
- 职责解锁卡：展示职责名 + 一句反差萌说明（如穷奇"门后怂包→举伞门卫"）。

**7. 依赖**
- 上游：照料系统（系统 2）提供 Trust/Heal 写入；收容系统（系统 1）提供档案与 duty 映射。
- 下游：transformed 状态 → 职责社交系统（系统 6，上岗）、图鉴系统（系统 7，前后对比）、经济系统（系统 4，职责产出）。

**8. 验收标准**
- [ ] 双轨正确累积且 HUD 双条实时更新。
- [ ] 仅当 Trust≥60 且 Heal≥100 触发蜕变；两门槛任一不足时给出明确非惩罚引导。
- [ ] 蜕变动画播放、职责解锁卡弹出、图鉴前后对比写入，三者一致。
- [ ] 祥瑞兽自在度分支与灵兽疗愈分支文案零冲突（引用 character-narrative）。

## 4. 经济 / 资源系统（Economy）　[Tier 3 · 精简八节]

**1. 概述**：管理单一货币「暖玉」与食材/材料两类资源，支撑喂食消耗、建造成本与委托奖励，是职责产出的吞吐中枢。
**2. 机制**：职责兽定时产出食材/暖玉（如饕餮厨房产食材、貔貅仓库理账产暖玉）；玩家消耗于喂食、建造、接委托；无债务、无破产（零失败）。
**3. 关键数据/数值**：货币 暖玉（示例初始 50）；食材 6 类（对应异兽食谱，待工程校准）；材料 用于建造。
**4. 公式/规则**：`产出 = BaseOutput(duty) × 环境加成`；`成本 = Lookup(建造项/委托)`；余额下限 0，不可负。
**5. 边缘情况**：余额不足时建造/委托置灰而非扣负；基础投喂不耗食材（防卡死）；离线产出按温和上限结算。
**6. UI 接口**：页签「背包/小仓库」展示暖玉与资源；建造/委托面板显示成本与可负担态；空仓库文案引用 character-narrative。
**7. 依赖**：上游 职责系统（系统 6）产出、疗愈（系统 3）解锁职责；下游 供建造（系统 5）、事件委托（系统 8）成本。
**8. 验收标准**：[ ] 货币/资源增耗闭环正确且不致负；[ ] 基础投喂不耗食材保最小可玩；[ ] 与系统 2 喂食消耗对账一致。

## 5. 建造 / 家园系统（Build / Home）　[Tier 4 · 精简八节]

**1. 概述**：玩家自由布置房间与设施，提供 `EnvBonus` 疗愈环境加成，是 SDT 自主的核心落点（我的收容所我做主）。
**2. 机制**：拖拽放置房间/家具/疗愈设施（柔灯、暖炉位、花园角）；设施等级提升 EnvBonus；无网格强迫，自由摆放。
**3. 关键数据/数值**：设施等级 1–3（每级 +5% EnvBonus，见 §0）；单房间 slot 数随等级 +1；初始 1 房间。
**4. 公式/规则**：`EnvBonus = 1 + 0.05 × Σ设施等级`；建造消耗暖玉/材料（系统 4）；slot 供给收容系统安置。
**5. 边缘情况**：空间占满仍可叠加装饰（不增 slot）；拆除返还部分资源（零惩罚）；祥瑞偏好设施（如麒麟莲池）给额外羁绊加成。
**6. UI 接口**：家园视图拖拽编辑；设施信息卡（等级/加成）；「搭一搭」页签与空建造文案。
**7. 依赖**：上游 经济系统（系统 4）供成本、疗愈（系统 3）解锁高级设施；下游 影响照料 EnvBonus（系统 2）、羁绊（系统 6）。
**8. 验收标准**：[ ] 设施等级正确换算 EnvBonus 并被系统 2 公式引用；[ ] 自由布置零惩罚、可拆除返还；[ ] SDT 自主可在 UI 验证。

## 6. 异兽职责 / 社交系统（Roles & Bond）　[Tier 4 · 精简八节]

**1. 概述**：蜕变后异兽上岗产出资源并彼此羁绊互动，把单兽疗愈升维为"收容所生态协作"，承担 SDT 关联落点。
**2. 机制**：上岗（duty 映射 beast-cast）→ 定时产出（系统 4）；羁绊 Lv1–5 经共处/协作/送礼/共完成委托增长（引用 character-narrative 羁绊表）；11 组羁绊关系触发合体动画与签名台词。
**3. 关键数据/数值**：羁绊 Lv1–5（初见/相识/信赖/依偎/家人）；增长全正向无衰减（零失败）；Lv5 解锁彩蛋故事（图鉴）。
**4. 公式/规则**：`羁绊 += f(共处时长, 协作上岗, 送礼匹配, 共委托)`；相邻/互补职责安排触发羁绊加速（如饕餮×貔貅「精算师联盟」）。
**5. 边缘情况**：不送礼绝不扣分；异兽未蜕变不可上岗；羁绊满级后仅维持（无溢出惩罚）；祥瑞兽羁绊走"做自己"支线。
**6. UI 接口**：页签「羁绊/牵挂」展示等级与关系；职责面板显示产出；合体动画与签名台词（引用 character-narrative ⑪组）。
**7. 依赖**：上游 疗愈（系统 3）解锁 duty、经济（系统 4）吞吐产出；下游 供图鉴（系统 7）彩蛋、事件（系统 8）共委托。
**8. 验收标准**：[ ] 职责产出接入经济闭环；[ ] 羁绊 Lv1–5 增长零失败且 Lv5 解锁彩蛋；[ ] 11 组羁绊关系可触发且与叙事文档零冲突。

## 7. 图鉴 / 收集系统（Codex）　[Tier 5 · 精简八节]

**1. 概述**：记录已收容异兽的典故、蜕变前后对比与羁绊彩蛋，是收集成长满足感与反差萌卖点的展示位。
**2. 机制**：收容即建卡（症状态）；蜕变后补「如今」对比图与职责；羁绊 Lv5 解锁隐藏彩蛋故事（引用 character-narrative 彩蛋段）。
**3. 关键数据/数值**：图鉴总槽 13（对应全阵容）；前后对比 2 帧；彩蛋解锁门槛 羁绊 Lv5。
**4. 公式/规则**：`卡片状态 = f(已收容, transformed, 羁绊等级)`；传说↔如今对照文案直接引用 character-narrative 图鉴表。
**5. 边缘情况**：空图鉴显示引导文案（"图鉴还空空的…"）；祥瑞兽无"疗愈前症状"对比，改为"初来→自在"对比；未蜕变仅显落魄态。
**6. UI 接口**：页签「图鉴/异兽册」网格；卡片翻面看前后对比；彩蛋故事弹窗（建议 ≤100 字适配移动端，待拍板）。
**7. 依赖**：上游 收容（系统 1）建卡、疗愈（系统 3）补蜕变、羁绊（系统 6）解锁彩蛋。
**8. 验收标准**：[ ] 前后对比与职责文案与 beast-cast/character-narrative 零冲突；[ ] 空状态与彩蛋解锁逻辑正确；[ ] 收集进度可见（SDT 胜任）。

## 8. 事件 / 委托系统（Events）　[Tier 5 · 精简八节]

**1. 概述**：推送新异兽委托、节日活动与访客到访，是收容系统的输入源与长线内容节拍器，保持慢节奏更新。
**2. 机制**：周期委托（接新兽，喂给系统 1）、节日活动（如「不浪费日」「掉毛派对」，引用 character-narrative 委托文案）、访客到访（触发短互动/羁绊）。
**3. 关键数据/数值**：委托节奏 1–2 现实日/只；活动周期按节日（待工程校准）；访客随机低频。
**4. 公式/规则**：`委托生成 = f(已收容数, 节奏)`；去重同系统 1；活动奖励写入经济（系统 4）/羁绊（系统 6）。
**5. 边缘情况**：委托堆积不强制（候接区无限）；活动过期可下年复现（零失败无损失）；访客拒绝仅本次跳过不罚。
**6. UI 接口**：页签「委托」与活动横幅；完成反馈文案引用 character-narrative（如「初雪的第一碗汤」完成语）。
**7. 依赖**：上游 无（自驱节拍）；下游 触发收容（系统 1）、经济（系统 4）、羁绊（系统 6）。
**8. 验收标准**：[ ] 委托正确生成并去重、喂给收容系统；[ ] 活动/访客文案与 character-narrative 一致；[ ] 所有边缘情况零失败。
