# 庭院整图素材 V1

参考母图：`design/山海·栖霞_UI运行基线_390x844@3/02_庭院主页.png`。沿用其水彩山林、中央石径、池塘，以及左上医馆、右上嬉游亭、左下梳洗台、右下百草园的构图；去除原设计里的 UI 和角色后，使用原生 ImageGen 生成完整场景及升级、光照版本。

`source/` 保存四种背景各三个等级的完整 PNG 原稿。`prompts.json` 记录参考图、生成约束和升级/光照提示词；master 字段为约束摘要，其余提示词为本次实际使用文本。原始生成输出保留在 Codex generated_images 中，工作目录保存独立副本。

## 运行方式

- 浏览器始终只显示一张已烘焙的完整庭院 WebP，不再绘制或缩放建筑立绘。
- 角色、文字标签、点击区域继续作为交互元素，全部以同一个 4:7 图片平面定位。
- 设施独立升级：`clinic, herb, groom, play` 四位数字分别代表医馆、百草园、梳洗台、嬉游亭等级，例如 `2132.webp`。
- 四种背景是 `courtyard / sunset / moonlit / fox-lantern-night`，每种 81 张，共 324 张。
- 运行图为 896×1568 WebP，总计约 110.4 MiB，最大单张约 397 KiB。首次只加载当前一张，打开升级预览或背景选择时才加载所需图片。

## 后续更新

使用带 `sharp` 的 Node 环境执行 `node scripts/bake-courtyard-art.js`，再执行 `node build-dist.js`。

烘焙脚本固定保留各主题一级母图的背景，只把对应设施的完整区域（建筑、基座、阴影）写入最终整图；区域边缘进行离线羽化。此步骤只在素材制作时发生。游戏运行时没有建筑图层拼接。

升级稿必须保持母图相机、画布比例、建筑位置不变；如果新造型超出 `scripts/bake-courtyard-art.js` 的区域边界，需要先调整区域并重新检查混合等级整图，不能直接替换旧图片。交互区域单独定义在 `prototype/js/merge/courtyard-art.js`，应覆盖相应建筑。

`art-contact-sheet.png` 展示四种主题的 `1111 / 2132 / 3333`，用于检查整图一致性。
