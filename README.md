# 小动物山海经 · 栖霞宗 H5

这是一个可直接运行的竖屏合成与神兽陪伴游戏。正式入口为 `prototype/merge_slice.html`，部署入口为 `dist/index.html`；`prototype/index.html` 仅是旧版照料原型，不属于正式验收范围。

## 运行与构建

```powershell
python -m http.server 8080
# 打开 http://localhost:8080/prototype/merge_slice.html

npm run build
# 构建后打开 dist/index.html
```

完整发布回归：

```powershell
npm run test:h5
node prototype/tests/h5_chapter_journey_v8_test.js
node prototype/tests/h5_item_source_invariant_v8_test.js
node prototype/tests/h5_daily_retention_v8_test.js
node prototype/tests/h5_save_recovery_v8_test.js
node prototype/tests/h5_analytics_privacy_v8_test.js
node prototype/tests/h5_browser_resilience_v8_test.js
```

## 正式内容契约

- 12 只神兽、12 卷篇章、14 个宗门区域；每只神兽有 5 个成长形态。
- 合成棋盘为 7×7，共 49 格；新档先开放 35 格，并至少保留一半可操作空位。
- 药材、药具、膳食、建材最高 10 阶；梳妆、陪玩、符箓、至宝最高 8 阶。订单和礼物阶位始终受所属家族上限约束。
- 卷一含山门、医馆两个区域，修缮从 0/6 开始；卷二四个区域为 0/12；其余有区域卷每区 3 段。无区域卷自动满足修缮条件，不显示虚假 0/9。
- 唯一卷章顺序：首次山门修缮 → 故事与本卷修缮 → 庭院照料 → 神兽蜕变 → 首次岗位 → 本卷完成与衔接演出。任一节点未完成都不能跳卷。
- 第一段故事在卷一山门首次修缮后开放；之后故事和修缮并行，照料必须等待三段故事与本卷全部修缮完成。
- “第一段结局”在前三只神兽篇章完成后解锁；“山海终章”仅在 12 只神兽全部完成后解锁。

## 玩法闭环

医馆五槽目标固定为“卷章、修缮、医案、访客、旅程”，“主线”只作为附加标记。全局顶部、订单、宗门和地图共同使用 `getCurrentObjective(state)` 给出的唯一下一步。

素材来源由 `resolveItemAvailability(state, requirement)` 统一解析为“现在可得、满足条件后可得、不可获得”。每项需求可点击查看来源、用途、解锁条件并直接前往；没有真实来源的物品不会进入订单。

正式产线包括永久生成器与高产增益型可耗尽生成器：

- 永久生成器在线点击消耗 1 点灵力，家族解锁时安全发放；旧档缺失时会幂等补发，满盘则进入待领取区。
- 生成器部件首次出现时成对发放，同阶二合一；高阶部件可组成高产、次数有限的增益生成器。
- 新档只有一处藤蔓和一把净化刷。藤蔓使用净化刷；封印格明确消耗暖玉。
- “九转还魂露”因暂无消费场景而在正式版本隐藏。

首局只有一个欢迎画面，随后直接进入宗门当前目标。教学依次引导生成、合成、山门首次修缮、去嬉游亭陪玩、在“玩具塔”中获得两枚 T1 并亲手合成 T2。山门首次修缮后正式获得穷奇。

系统按实际需要逐步开放：山门首修开放第一段故事和嬉游亭；医馆首修开放医案；第一段故事开放访客；第一只神兽蜕变开放旅程；配方、部件、储物与扩建在首次需要时提示。

庭院命名统一为：设施“嬉游亭”、活动“陪玩”、小游戏“玩具塔”。玩具塔使用 5 格槽，三张相同自动消除；界面显示“今日剩余奖励 3/3 次”。梳洗台使用交换消除玩法。两个小游戏均按需加载，弱网时显示进度和安全重试，加载失败不会扣除灵力。

## 日常、存档与隐私

- 每日三目标每天可领取一次，固定合计为暖玉 80、宗门阅历 33。
- 前七个不同领取日额外发放七日约定奖励；第 8 天起每日奖励继续有效，七日加奖不再重复。
- 所有领取先校验再改状态；失败调用不会改变领取标记、货币、物品或存档。
- 奖励灵力可暂时超过上限；自然恢复在降回上限前暂停，奖励不会被吞。
- 好感永不因离线或未互动下降；欢迎回来只结算正向设施与岗位产出。
- v8 存档支持幂等迁移、最近三份有效备份、JSON 导出/导入/恢复。高版本存档以只读模式打开，可导出或安全重开。
- 匿名统计可在设置中关闭，使用随机可重置安装 ID 与会话 ID，批量同源上报到 `POST /api/events`；不会上传完整存档、自由文本或设备指纹。

## 主要文件

- `prototype/js/merge/data.js`：物品、配方、神兽、区域与数值配置
- `prototype/js/merge/core.js`：状态机、资源闭环、日常和迁移契约
- `prototype/js/merge/ui.js`：浏览器交互、导航、设置与延迟加载
- `prototype/js/merge/save-store.js`：校验、备份、导入导出
- `prototype/js/merge/analytics.js`：匿名有限事件批量上报
- `prototype/merge-slice.css`：手机自适应界面
- `build-dist.js`：正式部署包与资源清单构建
