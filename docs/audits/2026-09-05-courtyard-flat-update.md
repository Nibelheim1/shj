# 庭院整图与独立升级交付

## 验收范围

以现有 UI 设计为参考，把四座建筑和基座画进整张庭院图；保留四座建筑各三级独立升级、四种背景、存档和角色互动。验证真实浏览器的小屏布局、升级扣费、加载失败和存档恢复。本次不执行安全检测。

## 完成内容

1. 新建 12 张完整场景原稿和 324 张可直接使用的 WebP 组合图。全部建筑自带正确基座、接地阴影；晨光、夕照、月夜、狐灯夜庭都支持任意等级组合。
2. 新增 `courtyard-art.js`，按当前设施等级与背景选择一张图片。图片与透明点击区域共用坐标平面，完整显示，不裁切；旧 CSS 强制建筑坐标已移除。
3. 升级弹窗展示当前/升级后外观。先加载下一张画面再执行原有升级，保留原始费用、产出和难度规则；重复点击不会重复扣费。
4. 加载失败保留上一张可用画面，提供重试；旧请求晚到时不会覆盖新选择。缓存最多保留 12 条加载记录，首次只请求当前场景。
5. 底部集中背景、今日、岗位、设施入口；住客切换移入对话气泡打开的详情面板，避免遮挡底部设施与按钮。角色点击动画保留。边缘与顶部背景颜色跟随主题。
6. 修正住客切换时九尾狐旧图集路径，使用现有 V14 正式图集。
7. 已更新正式 `dist/index.html` 及其资源、脚本，构建包含 1172 个文件。未上传或发布远端。

## 验证结果

- `courtyard_flat_runtime_test.js`：prototype 与 dist 实际浏览器均通过。测试使用隔离的明确注入存档，目的是验证庭院机制，不冒充自然通关记录。
- 校验 324 个组合均有唯一文件映射；初次加载只请求当前一张整图。
- 320×568、390×844、430×932：整图保持 4:7；四个点击中心与图上坐标一致、未被遮挡，触控尺寸至少 44px。
- 四座建筑入口和住客切换可用；九尾狐动画图集真实解码成功。
- 八次升级实际点击完成，逐次核对只变更目标设施等级与准确暖玉费用；满级不可继续升级。
- 升级图片失败不扣费；背景加载失败保留旧图并可重试；快速切换时晚到的图片不会覆盖最后选择。
- 四种背景切换不改变设施等级；刷新恢复背景、等级及暖玉。
- 场景控制器测试、DOM 冒烟测试与 HUD 八种状态回归通过；相关脚本语法检查通过。
- 查看真实运行截图、四主题混合等级联系图及满级画面，确认无运行时建筑立绘叠加。

截图目录：`output/ui-v14/courtyard-flat/prototype/`、`output/ui-v14/courtyard-flat/dist/`。

## 素材维护与实际限制

- 324 张运行图总计约 110.4 MiB；玩家按需下载，当前单张最大约 397 KiB。原稿和离线烘焙工具不进入发布包。
- 矮屏幕保留完整画幅，因此两侧有随主题配色的留边；常见 390×844 屏幕接近满宽显示。
- 以后增加第四级或第五种背景需补充原稿并重新烘焙；当前实现对应项目现有的三级设施与四种背景。

复现：`npm run test:ui:courtyard`；部署目录验证可设置 `H5_ENTRY=dist/index.html` 后执行相同命令。需要项目现有的 Playwright Node 依赖。
